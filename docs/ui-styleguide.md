# UI Styleguide — CHAVI Client

Canonical visual system for the application. Live preview at `/styleguide/` (staff only).

## Palette

All colors derive from five base colors. Each has a full 50–900 shade scale
(`chavi-{name}-{shade}`) defined in `staticfiles/js/tailwind.config.js`.

| Token | Hex | Role |
|---|---|---|
| `chavi-charcoal` | `#264653` | Dark chrome: navbar, table header bands, structural text, info |
| `chavi-primary` (Verdigris) | `#2a9d8f` | Primary actions, links, success, interactive hover |
| `chavi-sun` (Tuscan Sun) | `#e9c46a` | Warnings, pending states, nav active underline |
| `chavi-sand` (Sandy Brown) | `#f4a261` | Accents, zebra rows, intermediate states |
| `chavi-peach` (Burnt Peach) | `#e76f51` | Danger, errors, destructive actions |

Surfaces: `chavi-canvas` `#f5f8f9` (page bg), `chavi-paper` `#fbf7f0` (warm alt).
Gradient: `chavi-gradient` (verdigris→charcoal) reserved for hero/progress accents.

**Never use** Tailwind default color scales (`blue-*`, `green-*`, `red-*`,
`yellow-*`, `purple-*`, `indigo-*`, `teal-*`, …) or hardcoded hex values in
templates. `python manage.py lint_ui` enforces this.

## Status → color mapping

| Meaning | Style |
|---|---|
| success / completed / stored | `badge`/`alert` style `success` (verdigris) |
| error / failed / rejected | `danger` (peach) |
| warning / pending / partial | `warning` (sun) |
| processing / info / neutral status | `info` (charcoal) |
| accent / intermediate | `accent` (sand) |
| no status / disabled | `gray` |

## Layout scheme (Cool Canvas + V6)

- **Page background**: `bg-chavi-canvas` (set on `<body>` in `base.html`)
- **Navbar**: `bg-chavi-charcoal-800`; brand + links left, bell + profile right.
  Active item = tight `border-chavi-sun-400` underline under the label text.
  Dropdown panels are `bg-chavi-charcoal-700`; all nav icons `text-chavi-primary-300`.
  Built from `nav_link`, `nav_dropdown`, `nav_dropdown_item`, `nav_mobile_item`
  components — `active_on` kwarg takes comma-separated resolver_match
  url_name/namespace patterns (e.g. `active_on="data_import,dicom_server"`).
- **Cards**: white (or `accent` kwarg → tinted `*-50` bg + `*-100` header/footer bands + 4px top bar).
  Header actions go in the `actions` slot beside the `title` kwarg — do NOT
  pass a `header` fill that re-creates the title layout.
- **Tables**: `.chavi-table` — charcoal-800 header band, white header text,
  sand-50 zebra rows, primary-50 hover. Diff/changed rows: `class="row-warning"`.
- **Filter bars**: white surface, sand-200 border, charcoal Apply button.
- **Pagination**: verdigris active page, gray controls.
- **De-identification entity tags**: `.deid-tag-*` classes in `chavi.css`
  (per-entity-type tint; generated by extractor review JS).

### `data-*` attributes

Any `data__<name>` kwarg on `button`/`icon_button` renders a `data-<name>`
attribute: `data__file_id=f.id` → `data-file-id="…"`. `KwargComponent`
collects them; a `data` dict kwarg is merged too.

### Tabs variants

- `href` in a tab item → anchor (page navigation)
- `onclick` → `<button onclick="…">` (existing JS switching, e.g. `showTab()`)
- `target` → `<button>` calling `chaviSwitchTab(target)` from `tabs.js`;
  panels opt in via `data-tab-pane="<target>"`

### Modal JS contract

The modal element always carries `flex`; `hidden` alone controls visibility
(`hidden` wins over `flex` in Tailwind's utility order). `openModal(id)` /
`closeModal(id)` helpers toggle `hidden` only — so legacy JS that toggles just
`hidden` stays compatible. Escape key and backdrop click close open modals.

### Rules

- `{% url %}` **cannot** appear inside component kwargs — declare
  `{% url 'name' as var %}` first, then pass `href=var`.
- Kwarg values are template vars or quoted literals only. Concatenate with
  `{% with x="a"|add:var %}`.
- When a component has multiple fills, wrap default content in
  `{% fill "default" %}` — don't mix loose text with fills.
- Preserve all element `id`s and JS hooks when converting markup
  (`data__*` kwargs keep `data-*` intact; `progress` id kwargs keep Celery hooks).
- Component templates inherit the parent context — a same-named context
  variable can leak into an HTML attribute if the kwarg isn't passed
  (e.g. `form` from a form view → `form="<html>"`). `KwargComponent`
  shadows attribute kwarg names (`id`, `name`, `value`, `title`, `type`,
  `href`, `target`, `onclick`, `hidden`, `disabled`, `form_id`) to `None`
  when absent — only explicitly-passed kwargs render. Use `form_id`, never
  `form`.
- Table cells: `px-4 py-3 text-sm`; `whitespace-nowrap` only on short columns
  (ids, dates, actions). Table headers: `px-4 py-3 text-left text-xs font-medium uppercase tracking-wider`.

## Boundaries

- **Django admin** uses Unfold — palette harmonized via `UNFOLD["COLORS"]` in
  `settings.py` (verdigris primary). Admin templates under `templates/admin/`
  are overrides; they can use `chavi-table` but not `{% component %}`.
- **django-allauth** uses vanilla element rendering — `allauth_ui` is removed
  from `INSTALLED_APPS`. The palette is applied by overriding
  `templates/allauth/layouts/{base,entrance,manage}.html` (which extend the real
  `base.html` — same navbar/dropdowns/JS) and
  `templates/allauth/elements/*.html` (styled h1/h2/p/button/field/table/panel/
  alert/badge/details/provider elements). `fields` elements render via
  `form.as_p` inside `.aa-fields`, styled in `chavi.css`; links inside
  `.aa-content` get verdigris.
- **Signup is closed** — `client_app/adapters.py` `AccountAdapter.is_open_for_signup()`
  returns False. `/register/` and `/login/` redirect into the allauth flow.
- **`record_grid_node` / `record_detail_body`** keep `{% include %}` recursion —
  the correct mechanism for recursive record trees.

## Lint

```bash
python manage.py lint_ui            # errors exit 1
python manage.py lint_ui --warnings-only
```

**Errors**: off-palette Tailwind color classes, hardcoded off-palette hex,
legacy `{% include 'components/…' %}` partials, slippers syntax.
**Warnings**: Bootstrap-like classes (`btn`/`form-control`), empty `href`,
`<table>` without `chavi-table`, raw pill spans (→ `badge`), raw `<details>`
(→ `accordion`), raw `fixed inset-0` overlays (→ `modal`/`loading_overlay`),
raw `<h1>` (→ `page_header`).

Suppress a warning on intentionally-raw markup with an inline
`<!-- ui-lint:ok reason -->` comment on the same line (heroes, JS-coupled
elements).
